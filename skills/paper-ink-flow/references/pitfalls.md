# 踩雷紀錄（症狀 → 原因 → 解法）

> 製作者：林彥廷｜timzz1208@gmail.com

## 視覺
1. **看起來廉價、有 AI 感** → 深藍底＋發光、沒有主次、只有一種字體、沒有材質、節奏都一樣 → 改成「紙與墨」：紋路紙、限色、印刷語言、宋體加黑體、輕重有別的節奏（visual-language.md）。
2. **開頭抓不住人** → 從黑畫面淡入，或第一格只有空畫面 → 第 0 格就是封面海報：大字提問，水流已經在跑；2 秒內完成「提問 → 斷裂 → 數字砸下」。
3. **轉折沒有力量** → 第二個顏色太早出現 → 群青只留給轉折。

## 字型
4. **中文字變成系統預設字體** → 字型沒有從本機載入；或用了 Google Fonts，但輸出環境沒有網路 → 用 npm 的 `@fontsource/noto-sans-tc`、`noto-serif-tc`，並由 `render.js` 開本機伺服器載入（範本已經這樣做）。
5. **大部分字對，少數字變預設字體** → 中文 web font 拆成很多子集，畫布只會用到「已經載入」的子集 → `render.js` 會先跑過整支片、收集 `fillText` 畫到的每個字，再逐一用 `document.fonts.load()` 預先載入。終端機印出 `fonts ok` 才算成功；出現 ⚠ 就要處理。
6. **印章上的「家」是預設字體** → 印章會快取第一次畫出來的圖；如果字型載入之前就畫了，快取到的就是錯的字 → `video.html` 在 `?render=1` 模式下不會自己先畫，等字型載好才呼叫 `renderAt()`。不要把這個改回來。
7. **用 `file://` 開頁面時字型讀不到** → 瀏覽器對 `file://` 的字型有限制 → 用本機 HTTP 伺服器開（`render.js` 已經這樣做）。只有在瀏覽器裡預覽時，才會用到 Google Fonts 備援。

## 旁白與對時
8. **旁白比畫面長** → 中文旁白的實際速度通常比估計慢 → 用 `TIME_MAP` 把劇情照比例拉長；粒子、水波、顆粒仍然用真實時間，流速才不會變慢。
9. **畫面和音效對不上** → `video.html` 和 `sound.py` 各有一份 `TIME_MAP`，改了其中一份 → 每次改完都跑 `python3 tools/sync_check.py`。
10. **AI 語音把數字念錯** → 稿子裡寫「40,000」 → 給語音的稿子寫「四萬」；畫面上才用數字。
11. **自動切句切錯** → 句子裡逗號的停頓，有時比句子之間的停頓還長 → `tools/voice_lines.py` 用「字數比例＋停頓長度」的動態規劃選切點，不要只取最長的幾個停頓。切完要對照畫面、實際聽一次。

## 聲音
12. **手機上聽不到重擊和心跳** → 手機喇叭放不出 100Hz 以下 → 低頻重擊加一層 140～700Hz 的中頻敲擊（`heartbeat()` 是範例）。
13. **旁白不清楚** → 背景太大聲 → ducking 約 -11 dB，人聲比背景大 12 dB 以上（`sound.py` 會印出實測值）。
14. **音效很廉價** → 用電子嗖嗖聲 → 跟視覺語言一致：紙、筆、木頭、印章、鐘。

## 輸出
15. **檔案太大，傳不上去** → 逐格顆粒讓壓縮效率很差（crf 17 時 30 秒約 106 MB）→ 用固定位元率 `--vbitrate 5.5M`（約 5～7 Mbps），成品 30 MB 以內。
16. **同一秒每次輸出都不一樣** → 畫面有累積狀態，或用了 `Math.random()` → 所有隨機都用 `hash(k, seed)` 或固定種子的 `rng()`，畫面只由時間決定。
17. **只看定格就宣稱完成** → 震動手感、節奏、音量平衡，定格看不出來 → 交付前請人實際播放、開聲音看一遍。

## 環境
18. **Playwright 版本對不上瀏覽器** → 已經預裝 Chromium 的環境（例如 Claude Code 雲端）用的是 `chromium-1194` → `package.json` 釘在 `playwright@1.56.1`。沒有預裝的環境，要先執行 `npx playwright install chromium`。
19. **找不到 ffmpeg** → `pip install imageio-ffmpeg`，`render.js` 和 `make.sh` 會自動找到；或設定 `FFMPEG=` 路徑。
20. **Windows 上的 bash 腳本不能跑** → 用 WSL 或 Git Bash；工作路徑不要有中文或空格；clone 時加上 `-c core.autocrlf=false`。

## 內容與發布
21. **保險內容踩到紅線** → 放了保費、保額、商品名，或「一定理賠」這類說法 → 照 compliance.md 做，並提醒使用者公開前走公司審核。
22. **還沒審核的影片已經公開** → 原始 repo 設成公開，影片和程式任何人都看得到 → 審核前把 repo 設成私人，或不要把成品放進公開 repo。
