# 製作流程（paper-ink-flow）

> 製作者：林彥廷｜timzz1208@gmail.com

範例：「家庭責任流」。成品長度 39.5 秒，旁白約 33 秒；劇情以 30 秒為基準，再依旁白拉長。

## 1. 開工前：資料包

至少要有下面這些，缺了就先問使用者：

```text
主題／一句話訊息：（例：收入中斷時，誰接住這些責任？）
長度：15～20 秒最好；有旁白就依旁白長度決定
核心效果：只選 1 個主效果（例：粒子水流＋決策分岔），最多再加 1 個輔助
視覺方向：沿用「紙與墨」，或指定強調色
分鏡表：時間｜畫面發生什麼｜畫面文字｜轉場
結尾：帳號、最後一句話
聲音：要不要音效、配樂、旁白
```

分鏡裡寫「畫面發生什麼」就好，不用寫技術名詞。

## 2. 故事結構（這類題材的骨架）

| 段落 | 劇情時間（30 秒基準） | 做什麼 | 範例 |
|---|---|---|---|
| 鉤子 | 0～0.9 | 第 0 格就是封面：大字提問，水流已經在跑 | 「如果明天停薪，你家撐得了幾個月？」 |
| 斷裂 | 0.9～3.4 | **提問 → 視覺斷裂（線被劃斷、墨點噴散、畫面一震）→ 巨大數字砸下** | 主要收入被朱紅斜線劃斷，「−40,000 元」砸進畫面 |
| 後果 | 3.4～7.4 | 狀態改變：水桶轉紅、水位下降 | 「收入停了，責任不會跟著停。」 |
| 選擇 | 7.4～20.2 | 選項一個一個點開，每個都有看得見的代價 | 動用存款（15 個月歸零）、賣房（多了房租、要搬家）、另一半多扛（長期兼職） |
| 轉折 | 20.2～25.6 | **第二個顏色第一次出現**，補上斷掉的地方 | 群青的「保障緩衝」接上水流，存款留著 |
| 結語 | 25.6～30 | 一句話收束＋帳號＋示意聲明，印章落下 | 「先說清楚要守住的生活，再確認正式保障方向。」 |

原則：
- 每一段只推進一個理解重點。
- 每個選擇都要演出「代價」，不能只換文字。
- 轉折色只在轉折出現，這樣它才有份量。

## 3. 換主題時要改哪裡

| 檔案 | 改什麼 |
|---|---|
| `video.html` | `TIME_MAP`、各段時間常數（`CUT`、`SLAM`、`CHOICES`）、`HEADLINES`（標題）、`INFO`（下方數字列）、各種關鍵影格表（`LEVEL_K`、`PRESS_K`…）、`drawHook()`、結尾文字、`furniture()` 的版頭文字 |
| `engine.js` | `L`（版面位置）、`PATHS`（流動路徑）、元件（`bucket`、`tank`、`node`、`stamp`…）。新題材需要的新物件也加在這裡。`COL` 是配色，只在換強調色時才改 |
| `sound.py` | `TIME_MAP`（必須和 `video.html` 一模一樣）、每個音效的放置時間（用劇情時間寫）、`VOICE_LINES`（旁白每句的來源秒數與放置時間） |
| `interactive.html` | 選用：互動模擬器，跟影片共用 `engine.js`，觀眾可以調整虛構數字 |
| `voice/lines.txt` | 旁白稿，一句一行 |

畫面一律寫成「時間 t 的函數」，不要有累積狀態，例如「每格加一點」。這樣才能逐格輸出，也能跳到任一秒檢查。
粒子由編號決定出生時間、速度、偏移（`stream()`），任何時間點都能重算。

## 4. 旁白

1. 中文旁白每秒約 4～5 個字，先算字數再排時間。
2. 交給 AI 語音的稿子，**數字寫成中文字**，例如「四萬」，不要寫「40,000」，避免念錯。畫面上可以用阿拉伯數字。
3. 旁白要貼著畫面上的字寫：靜音看字的人和開聲音聽的人，拿到同一個故事。
4. **請使用者先生成旁白**，整段一個檔案，存成 `voice/narration.wav`，再開始對時。
5. 旁白通常比預期長。範例的 30 秒畫面配上 33 秒人聲，最後把畫面拉長到 39.5 秒。

## 5. TIME_MAP：讓劇情配合旁白

```js
// 真實時間（秒） → 劇情時間（30 秒版）
const TIME_MAP = [[0, 0], [2.05, 0.9], [2.75, 1.6], [5.2, 3.4], [10.7, 7.4], [12.6, 8.2],
  [18.5, 12.2], [22.6, 16.2], [27.0, 20.2], [33.9, 25.6], [39.5, 30]];
```

1. `python3 tools/voice_lines.py voice/narration.wav voice/lines.txt` 會量出每句旁白的起訖時間。它用動態規劃選切點：每段長度要符合字數比例，並偏好較長的停頓。輸出可以直接貼進 `sound.py` 的 `VOICE_LINES`。
2. 決定每句旁白在劇情裡要對到哪個段落，例如「動用存款？」要落在劇情 8.2，也就是第一個選項被點開的時候，把這些對應點寫成 `TIME_MAP`。
3. `VOICE_LINES` 的第三欄是「放置時間」（真實秒數），要跟 `TIME_MAP` 的對應點一致。
4. **劇情照比例拉長，但粒子、水波、顆粒用真實時間**。`renderAt(rt)` 裡劇情用 `story(rt)`，流動用 `rt`，這樣拉長後流速不會變慢。
5. `video.html` 和 `sound.py` 的 `TIME_MAP` 必須相同：`python3 tools/sync_check.py`。

## 6. 關鍵畫面先行

每一段先輸出一張定格（`node render.js --frames …`），排成總覽圖給使用者看。全部通過再做動態細節和聲音。
這樣省時間，也省 token。

## 7. 聲音（sound.py）

- 全部用程式合成：紙張翻動（`swish`）、筆劃（`slash`）、木質敲擊（`wood`）、木琴（`marimba`）、鐘（`bell`）、低頻重擊（`sub`、`slam`）、印章（`stamp_hit`）、心跳、和弦墊底（`pad`）、墨點流動的細碎聲（`flow_texture`，密度跟著畫面的粒子流）。
- 聲音要跟視覺語言一致：紙與墨就用紙、筆、木頭，不用電子嗖嗖聲。
- 情緒用和聲帶：開頭小調 → 斷裂時和弦瞬間抽掉 → 緊張的持續音 → 轉折時轉大調、鐘聲 → 結尾收在大三和弦。
- 手機喇叭放不出 100Hz 以下，低頻重擊要加一層中頻敲擊才聽得到（`heartbeat()` 就是範例）。
- 旁白說話時，背景壓低約 11 dB（ducking），人聲要比背景大 12 dB 以上，`sound.py` 會印出實測值。
- 用法：`python3 sound.py build/sfx.wav --voice voice/narration.wav --mix build/mix.wav`

## 8. 輸出

- `node render.js --out build/silent.mp4`：60fps，`--vbitrate 5.5M`（預設）。
- 逐格顆粒會讓檔案暴增：用 crf 17 時，30 秒約 106 MB。所以一定要用固定位元率，壓到約 5～7 Mbps。
- `make.sh` 會把畫面和混音合成 `output/<名稱>.mp4`，再執行 `tools/check.py`。

## 9. 驗收

1. `tools/check.py`：1080×1920、檔案 30 MB 以內、峰值 ≤ -1 dBTP，issues 要是 0。
2. `tools/sync_check.py`：兩邊的 TIME_MAP 一致。
3. 每一段的定格總覽：標題有沒有被 IG 介面擋住、數字和水桶標籤會不會相撞、第 0 格是不是一張完整的封面。
4. **請人實際播放、開聲音看一遍**。只靠定格判斷不夠，震動手感、節奏、音量平衡都要真的看過、聽過。
5. 保險、財經題材：確認 compliance.md 的每一項都做到，並提醒使用者公開前走公司審核。

## 10. 修改時用「導演指令」

「覺得普通」這類回饋改不出東西。請使用者，或你回報時，用可以直接執行的說法：

| 指令 | 意思 |
|---|---|
| 硬切 | 直接換畫面，沒有過渡 |
| 猛推／猛拉 | 一兩格內突然放大或縮小 |
| 緩推／緩拉 | 慢慢放大或縮小 |
| 速度 0.7 倍 | 這段動作放慢 |
| 停 N 格 | 畫面定住 N 格（60fps 時 1 格約 0.017 秒） |
| 震動加重／減輕 | `shake()` 的振幅 |

## 11. 互動模擬器（選用）

`interactive.html` 跟影片共用 `engine.js`，觀眾可以調整虛構數字、切換中斷情境、比較四條路。
可以把它當成貼文的延伸連結，或做成網站上的工具。

## 12. 交付

- 交付內容：`output/<名稱>.mp4`、`build/mix.wav`（完整混音）、`build/sfx.wav`（沒有旁白，方便在剪輯軟體換旁白）、定格總覽、README（分鏡表、旁白時間表、音效表、聲明）。
- 範本的 `README.md` 已經有這些表格的格式，照著填。
