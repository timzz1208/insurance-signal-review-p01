# 風格與分鏡設計指南（必讀）

程式只能保證「畫得出來」，這份文件定義的是「長什麼樣子才對」。
這份指南是在比對一支用同一套程式、卻做成「資訊卡簡報」的作品之後寫的（見文末的對照例子）。

## 1. 不可以拿掉的四件事（風格的核心）

1. **手繪抖動（line boil）**：`renderFrame()` 每一格都要呼叫 `boil(frame)`（每 3 格換一次雜訊種子）。它不是裝飾，而是「手繪動畫」的質感本身。不可以因為「抖動不算有意義的動作」就關掉。
2. **每一張至少一個具體的比喻物件**：人物、日常物品，或能代表概念的東西（傘＝健保、腳印＝教學留下來、水桶＝現金流、蝸牛＝慢慢來）。**只有方框＋文字＋箭頭的場景，不合格。**
3. **線條一筆一筆畫出來**：物件出現時用 `S(d, p)` 讓 p 從 0 畫到 1。不要只用淡入。
4. **米白紙紋理＋深墨線＋一個主色＋一個警示色**：警示色只用在語意上是警示的詞。不要換成其他配色。

使用者或其他指令說「移除裝飾性動作」時，指的是無意義的彈跳和旋轉，**不包括**上面這四件事。有疑慮時，先問使用者。

## 2. 從一句旁白到一個畫面事件（分鏡方法）

每一句旁白都要回答三個問題，寫在 `scenes.js` 該場景的註解裡：

| 問題 | 例子（「先扶一段，站穩了再慢慢放手」） |
|---|---|
| 這句話的**具體比喻**是什麼？要找能畫出來的東西或動作 | 老師牽著學生走一段路 |
| 這句話裡的**狀態改變**是什麼？要從 A 變成 B | 牽手 → 放手 → 老師指方向 → 學生自己走 |
| 事件要**對準哪個字**？ | 「扶一段」時牽手走，「放手」時手分開 |

找比喻的順序：
1. **這個抽象概念在生活中長什麼樣子？** 依賴 → 一直冒出來的問號泡泡；資訊過量 → 越疊越高的書、把人淹沒的紙堆。
2. **能不能用「前後對比」表現？** 例如一堆問號泡泡爆掉，換成一張被切成四塊、逐塊打勾的卡片。
3. **能不能有一個角色去做這件事？** 有人物在做事，比方框在移動更容易讓人理解。
4. 真的找不到比喻時，才用圖表，而且圖表本身也要會動（長條圖長高、線被畫出來、點沿著線走）。

**事件時間**：用 `ls(sc, i) + ld(sc, i) * 比例` 對準句子裡的關鍵字。例如某個關鍵字在句子 57% 的位置，就寫 `L1 + D1 * 0.57`。不要所有東西都在句子開頭一起出現。

## 3. 版面數值（Reels 1080×1920）

| 項目 | 數值 |
|---|---|
| 內容中心 | x = 540（場景以 510 撰寫，`REEL_DX = 30`） |
| 文字寬度上限 | 840px |
| 主標題 | 56～76px，粗體（同色描邊） |
| 副標／強調句 | 44～54px |
| 標籤 | 30～46px |
| 小字（出處、註解） | 21～28px，`TH.faint` |
| 字幕 | 54px（放不下時降到 50、46），框底 y = 1530 |
| 上方文字區 | y 250～560；畫面主體 y 560～1340；字幕區 y 1370～1530 |
| 線寬 | 物件外框 2.4～3.4；細節 1.2～2；強調線 4～7 |
| 色塊（`wash`）透明度 | 0.12～0.55（色塊不要蓋過線條） |

**畫面主體要佔滿 y 560～1340 大部分的面積。** 大片空白只能出現在刻意停頓的時刻，不能變成常態。

## 4. 動作語彙

| 要表達 | 用什麼動作 |
|---|---|
| 出現 | 線條畫出（0.4～1.0 秒）＋色塊淡入 |
| 強調 | 手繪圈圈（`scribbleRing`）、底線、打勾、微幅放大後回彈（1.12 → 1） |
| 否定 | 手繪打叉、劃掉的線（墨色或警示色） |
| 移動、流動 | 沿弧線移動（加一點上拋）、虛線流動（`stroke-dashoffset`） |
| 持續狀態 | 輕微漂浮（振幅 3～6px）、角色呼吸般的微晃、繞圈的點 |
| 鏡頭 | 整個場景緩慢推近 1.00 → 1.02～1.05 |
| 轉場 | 0.25 秒交叉溶接（`XF = 0.25`）。**不要用整頁推移**，那會像在滑簡報 |

每一個時間點，畫面上都要有東西在動（至少要有漂浮或手繪抖動）；每一句旁白都要有自己的事件。

## 5. 看圖修改的循環（每支片至少 3 輪）

每一輪都要實際**看**截圖，不能只讀程式：
1. 每個場景的完成狀態（加 guides）
2. 同步表：每句旁白播到 60% 的那一格
3. 重點區域的原尺寸裁切
4. 輪播 5 張的總覽

每一輪都問這五個問題：
- 這一張只看畫面、不看字，能看懂在講什麼嗎？
- 有沒有一個具體的比喻物件？
- 有沒有 1 秒以上什麼都沒發生？
- 有沒有東西相撞、太小、太空？
- 手機上縮小成 1/3 還看得清楚嗎？

**QA 回報 0 個問題只代表「沒有錯」，不代表「好看」。** 自動檢查通過之後，還是要用上面的問題判斷畫面好不好。

## 6. 對照例子：不要做成這樣

`review/codex-strengths-feedback-analysis`（「別急著補短板，先找出你的超預期」v2）：
- 程式和檢查都沒問題（QA 0、layout 0），查證也很嚴謹，輪播的工作表設計很有收藏價值。**這些都值得學。**
- 但影片的 5 個場景全部是「方框＋文字＋箭頭」：拿掉了 v1 原有的人物和傘，**也關掉了手繪抖動**，轉場改成整頁推移。結果看起來像動態簡報，不像手繪動畫。
- 改法示意（「寫下預期 → 對照結果」）：與其畫兩個方框，不如畫一個人在行動前把預期寫在紙條上、投進信封；事後拆開信封，把紙條和實際結果並排，然後在相同的地方打圈。這樣有角色、有物件、有前後狀態的改變。
