# 別急著補短板，先找出你的超預期

IG `@timzz1208`｜觀念型、可收藏、不推銷

本資料夾是以繁體中文、教育部標準字形（芫荽 Iansui）製作的手繪線稿 Reels 與 4:5 輪播。內容把「德魯克回饋分析法」改寫成一個低門檻的自我觀察練習：不要只問自己哪裡不夠好，先留下「預期／實際」紀錄，再從多筆結果找出可重複的能力線索。

## 旁白稿

每句一行、每句控制在 30 字內；成品時間以實際 TTS 波形為準。

> 你一直在補短板，卻可能補錯了地方。<br>
> 先問一個更有用的問題：<br>
> 什麼事，你總是做得比預期好？<br>
> 很多人只記得哪裡不夠好。<br>
> 但自我評估本來就不一定準。<br>
> 只靠感覺，很難看見自己的強項。<br>
> 德魯克提出一個簡單的方法：<br>
> 重要行動前，寫下你預期的結果。<br>
> 之後再把實際結果，拿回來對照。<br>
> 不要被一次成功說服，也不要被一次失敗定型。<br>
> 把幾次紀錄放在一起，看重複出現的模式。<br>
> 哪些任務、情境、做法，常常超出預期？<br>
> 強項不是自我感覺良好。<br>
> 它是被結果反覆驗證的能力線索。<br>
> 下一次，先把時間放到這條線索上。<br>
> 不是放棄短板，而是先找到你的高槓桿。<br>
> 收藏這套問題，下一次行動前拿出來。

## 事實查證表

| 成品主張／設計 | 判定 | 採用依據與限制 |
|---|---|---|
| 重要行動前記下預期，之後比較實際結果 | **可採用** | Peter F. Drucker〈Managing Oneself〉：HBR 1999 原文／2005 `Best of HBR` 重刊都把 feedback analysis 定義為 key decision/action 前寫下預期、之後比較實際結果。原文以 9 或 12 個月為例；本片沒有把 9／12 個月當成硬性規則，只保留「之後回看」。 |
| 多筆紀錄可用來辨識反覆出現的能力線索 | **可採用，但屬方法化表述** | Drucker 原文說持續實行後可看見 strengths、能力與習慣；本片把它轉成「多筆紀錄找模式」，是忠於原理的創作改寫，不宣稱一次結果就能判定強項。 |
| 只靠感覺做自我評估可能失準 | **可採用** | Karpen (2018) 的開放取得回顧整理自我評估與外部標準常只有弱到中度關聯，並指出自我知識容易受無意識偏誤影響。這不是說每個人都一定高估自己，也不是本片的個人診斷。 |
| 使用個人強項與工作表現、員工福祉呈正向關聯 | **可採用，但不等於因果保證** | Rudolph, Friedrich, Koziel et al. (2025) 的 meta-analysis 報告 strengths use 與 work performance、worker wellbeing 的正向關聯（ρ = .421、.621），且未支持「strengths overuse」的非線性關係。這項研究不是 Drucker feedback analysis 的直接驗證；本片不放效應量、不保證收入或成功。 |
| 不要被一次成功／失敗定型 | **編輯防誤導句** | 是本片為避免過度解讀單次結果而加的操作護欄，不是研究中的固定次數規則，也不宣稱每次結果都能排除運氣與情境。 |
| 「哈佛追蹤 2,000 人、優勢投入者收入增速 3 倍」 | **刪除，不採用** | 已用中英文變體與 Harvard／Drucker／strengths／income 等關鍵字檢索，未找到可核對的原始研究、作者、年份、研究設計與數據頁碼；搜尋摘要與二手貼文不足以支撐。成品不使用 2,000 人、10 年、80%、3 倍收入等數字或歸因。 |

## 內容邊界

- 本片是觀念與自我觀察練習，不是心理測驗、職涯診斷或收入承諾。
- `strengths use` 研究與 Drucker 的 feedback analysis 不是同一個研究構念；影片把它們並列為「原始方法＋研究補充」，沒有宣稱後者證明前者。
- 「先找強項」不等於永遠不補短板。Drucker 原文也要求補足實現強項所需的知識、技能，並修正妨礙績效的壞習慣。
- 本專案不出現保險商品或公司名稱，也不含推銷 CTA。
- 影片中不使用未查證的 Harvard、2,000 人、10 年、80%、3 倍收入說法。

## 重跑方式

在本資料夾安裝 Node 套件後，以本機已安裝的 Python 套件與模型執行：

```text
npm install
MODELS_DIR="C:/Users/Public/hermes_models" CHROME_PATH="C:/Program Files/Google/Chrome/Application/chrome.exe" ./make.sh
```

模型為暫用離線 Kokoro 中文 TTS 與 Paraformer 中文 ASR。Windows 上 Sherpa-Onnx 對含中文的模型路徑曾退回 `/usr/share/espeak-ng-data`，因此本機採用 ASCII 路徑 `C:/Users/Public/hermes_models`；這不是內容資料夾，也不含憑證。`make.sh` 會產生時間軸、ASR 對照、音訊、MP4、SRT、5 張輪播與 QA 報告。正式發布前應以真人旁白取代暫用 TTS，再重跑同一時間軸驗證。
